# Конфигурация

Приложение запускается с одним аргументом — путём к главному конфигу:

```
./build/sheremetevo-app configs/app.ini
```

Настоящие конфиги (`configs/app.ini`, `configs/config_infer_primary_yolo.txt`,
`configs/warper*.toml`, `configs/calibration/*.csv`) содержат адреса и калибровку
конкретной установки и в git не хранятся. В репозитории лежат шаблоны `*.example`.

| Файл | Кто читает | Шаблон |
| :--- | :--- | :--- |
| `configs/app.ini` | приложение | [`app.ini.example`](../configs/app.ini.example) |
| `configs/config_infer_primary_yolo.txt` | `nvinfer` | [`config_infer_primary_yolo.txt.example`](../configs/config_infer_primary_yolo.txt.example) |
| `configs/warper.toml` (можно свой на камеру) | `nvdewarper` | [`warper.toml.example`](../configs/warper.toml.example) |
| `configs/calibration/cameraN.csv` | приложение | [`camera.csv.example`](../configs/calibration/camera.csv.example) |
| `configs/app.test-video.ini` | приложение | пример прогона трекера на тестовом видео |

## app.ini

Формат INI (GKeyFile, как у конфигов DeepStream). Комментарии начинаются с `#`.
**Относительные пути считаются от папки, где лежит сам `app.ini`**, а не от текущей
папки. Ключи без значения по умолчанию обязательны. Ошибка в конфиге выводится
при старте с именем группы и ключа, например
`Cannot load config: configs/app.ini: [udp] port must be in 1..65535`.

### [app]

| Ключ | По умолчанию | Описание |
| :--- | :--- | :--- |
| `nvinfer-config` | обязателен | Конфиг `nvinfer`. Пути внутри него `nvinfer` считает от папки этого файла |
| `frame-width` | `1728` | Ширина кадра в пачке `nvstreammux`, > 0 |
| `frame-height` | `2752` | Высота кадра в пачке `nvstreammux`, > 0 |
| `batched-push-timeout-us` | `40000` | Сколько `nvstreammux` ждёт отставшую камеру, мкс. Разумно — один-полтора интервала между кадрами (40000 при 25 fps) |
| `class-id` | `4` | Класс детектора, который считается самолётом (4 — `airplane` в COCO). Объекты других классов не отправляются. `-1` — любой класс |

Все камеры приводятся к одному размеру `frame-width` × `frame-height`. В этих же
координатах детектор отдаёт рамки и в них же должны быть заданы пиксели
калибровочных точек (см. [calibration.md](calibration.md)). Если у камеры включён
`nvdewarper`, его выход тоже должен быть этого размера.

### [rtsp]

Необязательная группа: переподключение камер.

| Ключ | По умолчанию | Описание |
| :--- | :--- | :--- |
| `stall-timeout-sec` | `10` | Камера без кадров дольше этого времени считается зависшей и перезапускается, > 0 |
| `reconnect-interval-sec` | `5` | Пауза перед повторным подключением после ошибки или зависания, > 0. Для видеовыхода — первая пауза перед перезапуском, дальше она растёт вдвое до 60 с |

### [logging]

Необязательная группа: журнал приложения. Подробнее о формате записей —
[monitoring.md](monitoring.md).

| Ключ | По умолчанию | Описание |
| :--- | :--- | :--- |
| `level` | `info` | Минимальный уровень: `debug`, `info`, `warning`, `error` |
| `format` | `text` | `text` — строки для чтения; `json` — одна JSON-запись на строку для Loki, ELK, `jq` |
| `file` | не писать | Файл журнала в дополнение к stdout/stderr. Папка должна существовать |
| `max-size-mb` | `50` | Размер, после которого файл ротируется; `0` — без ротации |
| `max-files` | `5` | Сколько старых файлов хранить: `app.log.1` … `app.log.<max-files>` |

`debug` и `info` выводятся в stdout, `warning` и `error` — в stderr. В Docker оба
потока собирает Docker со своей ротацией, поэтому `file` там обычно не нужен.

### [metrics]

Необязательная группа: метрики в формате Prometheus. Список метрик —
[monitoring.md](monitoring.md).

| Ключ | По умолчанию | Описание |
| :--- | :--- | :--- |
| `enabled` | `false` | `true` — открыть HTTP-порт с метриками |
| `bind-address` | `0.0.0.0` | IPv4-адрес, на котором слушать; `127.0.0.1` — только с этой машины |
| `port` | `9464` | Порт, 1..65535. Метрики отдаются по `GET /metrics` |

Если порт занят, приложение не запускается и пишет причину в журнал.

### [output]

Видеовыход с разметкой: рамки, id трека, уверенность, точка касания и её координаты.

| Ключ | По умолчанию | Описание |
| :--- | :--- | :--- |
| `enabled` | `true` | `false` — без видеовыхода; кодирование и отрисовка не выполняются, это быстрее |
| `uri-prefix` | обязателен при `enabled=true` | Адрес публикации на RTSP-сервере. Камера N публикуется как `<uri-prefix>_<N>` |

Приложение само не раздаёт RTSP, а публикует поток на внешний сервер (например,
MediaMTX) через `rtspclientsink`. Схема `rtspt://` — RTSP поверх TCP, `rtsp://` —
по UDP.

### [udp]

Получатель сообщений с координатами: датаграммы protobuf по схеме `proto/points.proto`
(формат и правила отправки — [output-format.md](output-format.md)).

| Ключ | По умолчанию | Описание |
| :--- | :--- | :--- |
| `host` | обязателен | IPv4-адрес получателя. Имена хостов не поддерживаются |
| `port` | обязателен | Порт, 1..65535 |
| `batch-interval-ms` | `1000` | Кадры копятся этот интервал и уходят пачкой; `0` — каждый кадр сразу |
| `max-datagram-bytes` | `1400` | Предел размера датаграммы, 256..65507 байт. 1400 проходит без IP-фрагментации |

### [geo]

| Ключ | По умолчанию | Описание |
| :--- | :--- | :--- |
| `ransac-threshold-m` | `10` | Порог RANSAC при построении гомографии, в метрах. Точки калибровки с ошибкой больше порога не участвуют в итоговой матрице, > 0 |
| `min-aspect-ratio` | `1.2` | Объект отправляется, только если ширина рамки / высота больше этого значения |
| `zone` | нет | CSV с вершинами зоны (`lng,lat`, минимум 3, по порядку обхода), в которой ожидаются объекты. Точки вне зоны не отправляются. Общая для камер, у которых нет своего `zone`. Без параметра фильтра нет. Шаблон: `configs/zone.csv.example`, подробнее в [calibration.md](calibration.md#зона) |

### [tracker]

Необязательная группа. Если её нет или `enabled=false`, трекер не добавляется и
`object_id` в сообщениях равен -1.

| Ключ | По умолчанию | Описание |
| :--- | :--- | :--- |
| `enabled` | `false` | `true` — добавить `nvtracker` |
| `ll-lib-file` | обязателен при `enabled=true` | Библиотека трекера, обычно `/opt/nvidia/deepstream/deepstream/lib/libnvds_nvmultiobjecttracker.so` |
| `ll-config-file` | обязателен при `enabled=true` | Конфиг алгоритма трекера |
| `width` | `960` | Ширина кадра для трекера, кратно 32 |
| `height` | `544` | Высота кадра для трекера, кратно 32 |

Готовые конфиги лежат в `/opt/nvidia/deepstream/deepstream/samples/configs/deepstream-app/`:

- `config_tracker_IOU.yml` — самый быстрый, теряет объект при перекрытиях и резких скачках;
- `config_tracker_NvSORT.yml` — фильтр Калмана, середина по скорости и качеству;
- `config_tracker_NvDCF_perf.yml` — ищет объект по внешнему виду, устойчив к перекрытиям
  и большим смещениям между кадрами; используется по умолчанию.

Размер кадра трекера лучше брать с теми же пропорциями, что `frame-width` × `frame-height`.

### [cameraN]

Одна группа на камеру: `[camera0]`, `[camera1]`, … Номера должны идти подряд с нуля.
Номер группы — это `camera_id` в сообщениях и номер входа `nvstreammux`.

| Ключ | По умолчанию | Описание |
| :--- | :--- | :--- |
| `uri` | обязателен | Адрес RTSP-потока камеры. Поток H.264 без B-кадров |
| `calibration` | обязателен | CSV с точками калибровки `pixel_x,pixel_y,lng,lat` |
| `flip-method` | нет поворота | Поворот/отражение `nvvideoconvert`, 0..7 (см. ниже) |
| `dewarper-config` | нет выпрямления | Конфиг `nvdewarper` для устранения дисторсии объектива |
| `zone` | `[geo] zone` | Своя зона камеры, формат как у `[geo] zone`. Пустое значение (`zone=`) — без фильтра по зоне для этой камеры |

Модули поворота и выпрямления добавляются в конвейер, только если их параметры заданы.
Порядок: сначала поворот, потом выпрямление.

Значения `flip-method` (точный список — `gst-inspect-1.0 nvvideoconvert` в контейнере):

| Значение | Преобразование |
| :--- | :--- |
| 0 | без изменений |
| 1 | поворот на 90° против часовой |
| 2 | поворот на 180° |
| 3 | поворот на 90° по часовой |
| 4 | отражение по горизонтали |
| 5 | отражение по диагонали `upper-right-diagonal` |
| 6 | отражение по вертикали |
| 7 | отражение по диагонали `upper-left-diagonal` |

Пример:

```ini
[camera0]
uri=rtspt://10.0.0.21:554/stream1
flip-method=1
dewarper-config=warper.toml
calibration=calibration/camera0.csv
```

## config_infer_primary_yolo.txt

Конфиг `nvinfer` для YOLO26. Пути в нём считаются от папки этого файла. Ключи, которые
приходится менять:

| Ключ | Значение |
| :--- | :--- |
| `onnx-file` | ONNX, экспортированный `models/export_yolo26.py` (см. [model.md](model.md)) |
| `model-engine-file` | Готовый TensorRT engine. Если файла нет или он не подходит, `nvinfer` строит engine из ONNX при старте |
| `labelfile-path` | `labels.txt`, создаётся скриптом экспорта |
| `batch-size` | Равен числу камер |
| `network-mode` | `0` — FP32, `2` — FP16 (быстрее, точность обычно почти не меняется), `1` — INT8 (нужна калибровка) |
| `filter-out-class-ids` | Все классы COCO, кроме 4 (`airplane`). Должно совпадать с `[app] class-id` |
| `cluster-mode` | `4` — без кластеризации: YOLO26 сам отдаёт итоговые рамки (NMS-free) |
| `custom-lib-path` | Путь к `libnvdsinfer_custom_impl_Yolo.so` из DeepStream-Yolo. В Docker-образе проекта — `/opt/DeepStream-Yolo/nvdsinfer_custom_impl_Yolo/libnvdsinfer_custom_impl_Yolo.so` |
| `pre-cluster-threshold` | Порог уверенности детекции, `0.25` |

`parse-bbox-func-name=NvDsInferParseYoloCuda` и
`engine-create-func-name=NvDsInferYoloCudaEngineGet` менять не нужно.

## warper.toml

Конфиг `nvdewarper` (формат описан в документации DeepStream, Gst-nvdewarper).
Параметры подбираются под объектив конкретной камеры; для разных камер можно завести
разные файлы. `output-width`/`output-height` и размер поверхности должны совпадать с
`frame-width`/`frame-height` из `app.ini`. Основное, что меняется:

- `projection-type` — тип проекции (`3` — перспектива в перспективу);
- `focal-length` — фокусное расстояние в пикселях;
- `distortion` — коэффициенты радиальной/тангенциальной дисторсии `k1;k2;k3;p1;p2`;
- `src-x0`, `src-y0` — оптический центр исходного кадра;
- `roll`, `yaw`, `pitch` — доворот камеры.

После изменения поворота или параметров выпрямления пиксельные координаты на кадре
меняются, и калибровку камеры нужно снимать заново.

## Тестовый прогон без камер

`configs/app.test-video.ini` — пример запуска на записанном видео: файл раздаётся как
RTSP через `ffmpeg` (с перекодированием без B-кадров), поворот и выпрямление не нужны.
Калибровка к видео не относится, поэтому координаты в сообщениях смысла не имеют —
так проверяют детекцию и трекинг. Команда для `ffmpeg` — в комментарии в начале файла.
